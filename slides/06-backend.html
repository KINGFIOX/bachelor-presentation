后端 — 乱序执行引擎总览

RV64IM，五条独立执行路径： ALU MDU BRU LSU (late) CSRU (late)。 流水线：译码 → 重命名 → 分派 → 发射 → 执行 → 写回 → (晚执行) → 提交， 每级用 PipelineConnect 时序解耦。

  • PRF：9 读端口 (ALU×2 / BRU×2 / MDU×2 / LSU×2 / CSRU)，5 写端口
  • FutureRAT：推测态映射；3 读端口（rs1/rs2/rd），1 写端口
  • ArchRAT：已提交确定映射；提交时同步更新
  • FreeList：分配/回收物理寄存器； flush 时仅 1 周期由 ArchRAT 重建
  • BusyTable：6 读 + 5 wakeup（即时/Exec/Late 三类时机）

old_prd 释放示例

指令 逻辑 rd 分配 prd old_prd
ADD x1, x2, x3 x1 p10 p1
SUB x1, x4, x5 x1 p11 p10

ADD 提交 ⇒ p1 (旧 x1) 已无引用 ⇒ 归还 FreeList； SUB 提交 ⇒ p10 归还。 每个活跃值独占一个物理寄存器，消除 WAW/WAR 假依赖。

flush 恢复：FutureRAT 从 ArchRAT 快照、FreeList 用 ArchRAT 反推， 仅 1 周期，无需遍历 ROB。

后端 — 发射队列与乱序发射（泛型抽象）

三个独立 IQ + 5 个 wakeup 源

ALU IQ
BRU IQ
MDU IQ
  • wakeup 源 1：分派级即时（LUI/AUIPC/JAL/JALR 结果可在分派算出）
  • wakeup 源 2-3：ALU / MDU 写回
  • wakeup 源 4-5：LSU / CSRU 延迟执行写回
选择策略：源就绪后，优先级编码器选最早入队，保证公平性。 "执行 → 唤醒 → 发射"形成连锁反应。

abstract class IssueQueue[T <: Data](

}

类型参数 gen: T 携带载荷差异（ALU 含立即数；BRU/MDU 不含）； 三个 IQ 复用同一份核心实现。 简单实现 = 固定槽位扫描；复杂实现 = 压缩表项（compacting），对外接口完全一致。

为什么 Store / CSR 走 late execution

  • Store：避免推测路径上对内存状态的不可撤销副作用，简化存储一致性维护
  • CSR：保证特权级切换、中断使能等副作用严格按程序顺序生效
  • 分派时仅写入 ROB，不入发射队列；ROB 推到提交头部时才交付 LSU/CSRU 执行

LSU 内部细节

  • 独立 dTLB + PTW，复用 IFU 的 PTW 实现（仅权限位检查不同）
  • Load 检 PTE.R，Store 检 PTE.W；mcause = 13 / 15
  • MMIO 与 DCache 路径在 lsu_req 分流

后端 — 提交级与精确异常

提交级（CommitStage）从 ROB 头部按程序顺序逐条提交，是乱序执行恢复顺序语义的关键环节。 每次提交执行以下 7 步：

1. 写 ArchRAT

逻辑 rd → 新 prd 映射写入 ArchRAT，确定性状态前进

2. 释放 old_prd

old_prd 归还 FreeList，供后续指令重命名

3. 异常注入

检测异常/中断 → 触发 trap，调 CSRU 写 mcause/mepc，redirect 到 mtvec

4. mret/sret

从 mepc/sepc 取返回地址，恢复特权级

5. fence.i / sfence.vma

对外发出 fence_i / sfence_vma，通知 ICache / iTLB 失效

6. 分支验证

BRU 实际结果 vs 前端预测；不一致 ⇒ redirect + flush

7. DiffTest probe

输出 PC / dnpc / inst / GPR / CSR 给 DiffTest 框架，与 Spike 逐条比对

异常严格在提交点处理：推测路径上的指令不会修改任何体系结构状态。 ⇒ 异常对程序员表现为在触发指令处精确发生（精确异常）。
