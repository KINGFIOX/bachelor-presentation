后端 — 乱序执行引擎总览

RV64IM，五条独立执行路径： ALU MDU BRU LSU (late) CSRU (late)
流水线：译码 -> 重命名 -> 分派 -> 发射 -> 执行 -> 写回 -> (晚执行) -> 提交

后端 — 寄存器重命名（统一物理寄存器）

统一物理寄存器, physical register file, prf

  • PRF：9 读口 (ALU×2 / BRU×2 / MDU×2 / LSU×2 / CSRU)，5 写口
  • FutureRAT：推测态映射；3 读端口（rs1/rs2/rd），1 写端口
  • ArchRAT：已提交确定映射；提交时同步更新
  • FreeList：分配/回收物理寄存器
  • BusyTable：6 读 + 5 wakeup（即时/Exec/Late 三类时机）

old_prd 释放示例

指令 逻辑 rd 分配 prd old_prd
ADD x1, x2, x3 x1 p10 p1
SUB x1, x4, x5 x1 p11 p10

ADD 提交 ⇒ p1 (旧 x1) 已无引用 ⇒ 归还 FreeList； SUB 提交 ⇒ p10 归还。 每个活跃值独占一个物理寄存器，消除 WAW/WAR 假依赖。

精确异常：FutureRAT 从 ArchRAT 快照、FreeList 用 ArchRAT 反推， 仅 1 周期，无需遍历 ROB。
技术选型：中期阶段我已实现基于“值捕捉（value-capture）”的寄存器重命名后端， 但该方案高度依赖旁路网络；随着设计规模扩大，旁路判断与连接复杂度迅速膨胀。 因此在结题阶段切换为基于 PRF 的重命名方案，以获得更好的可扩展性与实现复杂度。

后端 — 发射队列与乱序发射（泛型抽象）

三个独立 IQ + 5 个 wakeup 源

ALU IQ
BRU IQ
MDU IQ
  • wakeup 源 1：LUI/AUIPC/JAL/JALR 结果可在分派时算出
  • wakeup 源 2-3：ALU / MDU 写回
  • wakeup 源 4-5：LSU / CSRU 延迟执行写回
为实现简单，目前采用 FIFO 的发射策略：选择双操作数就绪的指令中，最早入队的指令发射

Chisel 泛型抽象类


abstract class IssueQueue[T <: Data](

类型参数 gen: T 携带载荷差异（ALU 含立即数；BRU/MDU 不含）； 三个 IQ 复用同一份核心实现。 简单实现 = 固定槽位扫描(纯 FIFO)；复杂实现 = 压缩表项（compacting），对外接口完全一致。

后端 — 延迟执行：LSU + CSRU

						stateDiagram-v2
						  idle --> tlb_check: Sv39 on
						  idle --> lsu_req: Sv39 off
						  tlb_check --> lsu_req: TLB hit ∧ access ok
						  tlb_check --> idle: page fault
						  tlb_check --> ptw_req: TLB miss
						  ptw_req --> ptw_wait: PTW fire
						  ptw_wait --> idle: PTW fault
						  ptw_wait --> tlb_check: PTW done(refill dTLB)

						  lsu_req --> idle: ack ∧ done
						  lsu_wait --> idle: done
延迟执行：分派时仅写入 ROB，不入发射队列； ROB 到提交头部时再交付 LSU/CSRU 执行，优先保证正确性与实现稳定性。

技术选型：当前采用最保守的晚执行实现

  • Store：本实现放在晚执行；工业实现常配合 Store Buffer，未必提交当拍写入 DCache
  • Load：通常可前移到执行级，这里采用了保守实现——延迟执行
  • MMIO：必须晚执行，避免推测路径对外设产生不可撤销副作用
  • CSR：可继续做前移优化，但出现频率低，当前按保守策略在提交点生效

LSU 内部细节

  • 独立 dTLB + PTW，复用 IFU 的 PTW 实现
  • Load 检 PTE.R，Store 检 PTE.W；mcause = 13 / 15
  • MMIO 与 DCache 路径在 lsu_req 分流

后端 — 提交级与精确异常

提交级（CommitStage）从 ROB 头部按程序顺序逐条提交，是乱序执行恢复顺序语义的关键环节。 每次提交执行以下 7 步：

1. 写 ArchRAT

逻辑 rd → 新 prd 映射写入 ArchRAT，确定性状态前进

2. 释放 old_prd

old_prd 归还 FreeList，供后续指令重命名

3. 异常注入

检测异常/中断 → 触发 trap，调 CSRU 写 mcause/mepc，redirect 到 mtvec

4. mret/sret

从 mepc/sepc 取返回地址，恢复特权级

5. fence.i / sfence.vma

对外发出 fence_i / sfence_vma，通知 ICache / iTLB 失效

6. 分支验证

BRU 实际结果 vs 前端预测；不一致 ⇒ redirect + flush

7. DiffTest probe

输出 PC / dnpc / inst / GPR / CSR 给 DiffTest 框架，与 Spike 逐条比对

异常严格在提交点处理：推测路径上的指令不会修改任何体系结构状态（ArchRAT）。 ⇒ 异常对程序员表现为在触发指令处精确发生（精确异常）。
