Flash 控制器与 XIP 机制

APB XIP 控制器状态转移图（8 态）

Flash 双访问模式：

  • 命令方式：经 APB → SPI Arbiter → SPI 寄存器，用于 Bootloader 阶段 Flash 编程
  • XIP 方式：CPU 对 Flash 地址窗口的 MMIO 读 → 自动转换为 SPI 命令字序列 → 直接取指
引入 XIP 的动机：避免"鸡生蛋"死锁——若程序在 Flash 中而访问 Flash 又依赖软件驱动， 则驱动本身需先从 Flash 取出，系统无法启动。XIP 提供硬件读通路，无需软件驱动即可启动。

基于 Winbond W25Q128JVSIQ 手册时序，实现行为级仿真模型并经类 UVM 验证，协议正确性可对接物理芯片。

PSRAM QSPI Master 控制器

PSRAM（Pseudo-SRAM） 通过 QSPI（Quad SPI）协议访问外部存储器。 本课题参考 OpenCores SPI 设计思路，使用 Chisel 重新实现完整 QSPI Master， 采用 APB 接口并支持 QSPI ↔ QPI（四线半双工）模式切换。

控制器内部由状态机统一调度两类核心子模块，完成 APB 事务到串行时序的映射：

FSM

协调 APB 总线事务与 SPI 传输流程，统一发出控制信号

Clgen

时钟分频器，生成 sClk 及 posEdge/negEdge 边沿时序

Shift

移位寄存器，完成串并转换并向 FSM 回传 tipDone/last

SDRAM 控制器：Chisel 完整重写 + 字位扩展

控制器支持位扩展与字扩展两种组织方式。位扩展模式下，两颗 SDRAM 芯片与同一个 SDRAM Core 组成一个 Bank，对同一行/列命令同步激活与访问，并在控制器侧将两路 16bit 数据拼接为 32bit 通路。

  • 字扩展（Low-order Interleaving）：两个 Core 并联，按地址低位将请求映射到奇/偶 Core
  • 事务桥路由：中间模块将 AXI4 事务转为 Core 请求，并依据 addr(2) 路由到目标 Core
  • 响应回收：请求发出时把 Core 选择写入 pending FIFO，回收对应 ack/readData/error 返回 AXI4 侧
