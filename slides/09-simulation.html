仿真验证平台 — 总体架构

工具链：Chisel —[CIRCT]→ Verilog —[Verilator]→ C++ 类 —[link]→ 仿真 binary

差分测试原理：处理器的双层状态机模型 —— ISA 状态机（Spike 实现，软件可见） vs physical 状态机（DUT 内部）。每条指令执行后 PC/mem/GPR 状态迁移；DUT 与 Spike 在每条指令后状态完全一致 ⇒ CPU 在软件程序员视角下正确。

以 Verilator（DUT）+ Spike（Golden Model）+ Capstone（反汇编）为基础 构建逐指令差分测试平台；结合 NVBoard 完成外设可视化联调， 扩展为"指令级 + 系统级"双层验证体系。均以静态库形式链接到仿真 binary。

仿真平台 — C++20 重构与模块划分

平台以 C++20 开发，遵循 Google C++ Style Guide， 使用 CMake 管理构建依赖，并引入 Abseil 作为基础设施库（字符串、日志、容器等）。

核心组件

  • ScoreBoard：提交后驱动 Spike，对比 PC/GPR/CSR ISA 状态
  • VerilatorCpu：封装 DUT，基于 probe 导出提交与寄存器观测点
  • Sdb：Readline + Flex/Bison，支持单步、断点、监视点、表达式求值
  • Tracer：I/M/D/F 四类追踪，统一环形缓冲回溯

工程化能力

  • 集成 NVBoard，支持 GPIO/UART/VGA 外设可视化联调
  • DiffTest 支持 MMIO 特殊路径（DUT 主导、参考模型跟随）
重构收益：在保持功能扩展速度的同时，代码结构更清晰、调试链路更稳定， 可支撑 DiffTest / 追踪 / 快照回放的长期迭代。借助 vibe coding，将 NVBoard 从 C99 升级为符合 Google C++ Style 的 C++20 代码，并支持通过 CMake 分发；同时将 Spike 的分发模式从 GNU autotools 重构为 CMake 分发模式，统一工具链与工程分发流程。

仿真平台 — LightSSS 快照回放 & DiffTest

环形缓冲区快照机制（基于 fork）

LightSSS 动机

仿真过程中波形与日志会迅速消耗磁盘（GB 级/分钟）； 但出错通常只关注最后一小段时间。

实现方式

  • 主进程定期 fork() 创建快照子进程（COW，内存零拷贝）
  • 仅保留环形缓冲中最近的 K 个快照
  • 出错时唤醒最近的子进程，开启日志/波形记录，运行至出错点
  • 最终输出包含最后 N 个周期完整波形的 VCD/FST
DiffTest + LightSSS 协同：DiffTest 检测到状态发散立刻触发回放， 定位"第一次发散指令"前的 K 拍完整波形 ⇒ 从天级 debug 缩短到分钟级。
