仿真验证平台 — 总体架构

工具链：Chisel —[CIRCT]→ Verilog —[Verilator]→ C++ 类 —[link]→ 仿真 binary

差分测试原理：处理器的双层状态机模型 —— ISA 状态机（Spike 实现，软件可见） vs physical 状态机（DUT 内部）。每条指令执行后 PC/mem/GPR 状态迁移；DUT 与 Spike 在每条指令后状态完全一致 ⇒ CPU 在软件程序员视角下正确。

以 Verilator（DUT）+ Spike（Golden Model）+ Capstone（反汇编）为基础 构建逐指令差分测试平台；结合 NVBoard 完成外设可视化联调， 扩展为"指令级 + 系统级"双层验证体系。均以静态库形式链接到仿真 binary。

仿真平台 — Rust 重写与模块划分

原 C99 实现约 5600 行，随 CPU 迭代维护成本上升。使用 Rust 重构，采用 面向对象 / 泛型 / 函数式 / RAII 范式，代码量减少至约 2500 行， 可读性与可维护性显著提升（通过 cloc 统计验证）。

代码树（按功能划分六个模块）


src/rust/
├── common      # 命令行参数 + 快照机制
├── ffi         # Verilator/Spike/NVBoard 桥接层
├── libcpu      # 抽象 CPU 模型（Spike + Verilator 统一接口）
├── libdpi      # DPI-C 回调（拦截 ICache、访存等）
├── libsdb      # 简易调试器（Flex/Bison 表达式 + 断点）
├── tracer      # ITrace / MTrace / DTrace / FTrace
├── lib.rs
└── main.rs

关键设计

  • libcpu：抽象 trait 统一 Spike 与 Verilator 操作接口，使 DiffTest 能以同一种方式驱动两者
  • libdpi：在 RTL 仿真中拦截 ICache 访问与外设访存，记录硬件行为
  • libsdb：内置 Flex/Bison 表达式求值引擎，支持寄存器/内存表达式断点与监视点
  • tracer 四类：指令、内存、设备、函数追踪，全部支持环形缓冲
Rust 类型系统使桥接 C/C++ 库时 lifetime 与所有权可静态校验， 消除原 C 版本的指针 use-after-free 类 bug。

仿真平台 — LightSSS 快照回放 & DiffTest

环形缓冲区快照机制（基于 fork）

LightSSS 动机

仿真过程中波形与日志会迅速消耗磁盘（GB 级/分钟）； 但出错通常只关注最后一小段时间。

实现方式

  • 主进程定期 fork() 创建快照子进程（COW，内存零拷贝）
  • 仅保留环形缓冲中最近的 K 个快照
  • 出错时唤醒最近的子进程，开启日志/波形记录，运行至出错点
  • 最终输出包含最后 N 个周期完整波形的 VCD/FST
DiffTest + LightSSS 协同：DiffTest 检测到状态发散立刻触发回放， 定位"第一次发散指令"前的 K 拍完整波形 ⇒ 从天级 debug 缩短到分钟级。
