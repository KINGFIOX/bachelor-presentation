缓存 — VIPT ICache（4 路组相联）

stateDiagram-v2
  idle --> lookup: in.req ∧ !fence_i (latch addr)
  lookup --> lookup: hit ∧ in.req
  lookup --> idle: hit ∧ !in.req
  lookup --> miss: miss
  miss --> replace: 1-cycle pass-through
  replace --> refill: out.ar.fire (start burst)
  replace --> idle: fence_i ∧ !out.ar.fire
  replace --> fence_drain: fence_i ∧ out.ar.fire
  refill --> idle: out.r.fire ∧ out.r.last (commit line, done)
  refill --> fence_drain: fence_i (abort commit, keep drain)
  fence_drain --> idle: out.r.fire ∧ out.r.last

ICache FSM（idle/lookup/miss/replace/refill/fence_drain）

结构 VIPT（Virtually Indexed, Physically Tagged）
组织方式 4 路组相联
缓存行 64 字节
组数 / 总容量 64 组 / 16 KB
替换策略 PLRU（伪 LRU，二叉树位）
突发传输 AXI4 WRAP 模式
WRAP 突发：从缺失地址开始传输，到达行末尾后回绕， 第一拍数据即可返回 CPU，最小化缺失延迟。
缓存级差分测试：通过 DPI-C 接口将硬件 PLRU 与 Rust 软件模型逐次比对 hit/replace 决策， 定位仅靠架构状态比对无法发现的替换策略缺陷。
fence_drain 的必要性：当 fence_i 到达时若 AXI 读突发已发出， 不能直接丢弃在途事务，必须继续接收直至 r.last。 否则总线侧响应无人消费，后续请求可能被阻塞并引发死锁。

缓存 — DCache（write-back + Write Buffer）

组织 VIPT 4 路 × 64 组 × 64B = 16 KB
写策略 Write-back + Write-allocate
状态数 7 态主状态机（含 flush 流程）
关键优化 Write Buffer：写命中不阻塞主 FSM
Write Buffer 机制：lookup 命中写时把 (index/way/beat/wstrb/wdata) 推入单项缓冲， 下一周期由独立 FSM 完成按字节掩码合并， 主 FSM 当拍即可接受下一请求。

7 态主状态机概览

stateDiagram-v2
  idle --> flush_scan: fence_i ∨ sfence_vma
  idle --> lookup: in.req ∧ !wb_conflict

  lookup --> lookup: hit ∧ in.req ∧ !wb_conflict
  lookup --> idle: hit ∧ (!in.req ∨ wb_conflict)
  lookup --> miss: miss

  miss --> replace: !victim_dirty
  miss --> replace: victim_dirty ∧ out.aw.fire

  replace --> refill: ar_sent ∧ b_received
  refill --> idle: out.r.fire ∧ out.r.last

  flush_scan --> flush_wb: fw_dirty ∧ out.aw.fire
  flush_scan --> flush_scan: !fw_dirty ∧ !scan_done
  flush_scan --> idle: !fw_dirty ∧ scan_done

  flush_wb --> flush_scan: wb_burst_done ∧ b_received ∧ !scan_done
  flush_wb --> idle: wb_burst_done ∧ b_received ∧ scan_done
  • replace 并行：W 通道写回脏数据 + B 等待回应 + AR 发起 refill 读
  • refill：R 通道逐拍写回 data bank；R.last 时更新 tag/valid/dirty + 推进 PLRU
  • flush 流程：fence.i / sfence.vma 触发，逐组逐路扫描，遇脏行就写回

缓存 — fence.i 与 DMA 一致性

fence.i：分离式 L1 的指令-数据一致性

典型场景 = Bootloader 拷贝指令到 SDRAM 后跳转执行（自修改代码）：

提交 fence.i -> CommitStage io.flush
DCache flush_scan -> wb -> ICache 整片 invalidate
IFU 重取指
RISC-V 将 fence.i 划入 Zifencei 扩展， 属于代价较高指令；本设计选择简洁实现，单核场景足够。

DMA <-> DCache 一致性（virtio-disk）

xv6 移植时引入 virtio-disk DMA，与 CPU 共享 SDRAM；DMA 与 DCache 之间无硬件协议。 问题表现：

  • CPU -> DMA：sw 写入数据被 DCache 吸收为脏行 -> DMA 从 SDRAM 读取仍是旧值
  • DMA -> CPU：DMA 写入 SDRAM 后 -> CPU 仍命中旧 DCache，看不到新数据
软件侧解决：在所有触发/终结 DMA 的 MMIO 前后插入 fence， 复用 DCache flush_scan→flush_wb 路径将脏行刷回 + 整片失效。 硬件侧不引入跨主设备同步结构。
